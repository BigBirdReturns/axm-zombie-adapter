axm-zombie-adapter

A lightweight control plane for zombie compute: turn salvaged consumer GPUs into a repeatable, inspectable inference plan. GPUs rarely die of physics — they die of driver EOL and software churn. This tool keeps the knowledge of how to run them in plain-text artifacts built to outlive every engine, vendor stack, and maintainer.

Try the demo GitHub Schema spec 30-year plan

What it does

It turns “I have some GPUs” into artifacts you can diff, version, and hand to an execution engine. The adapter is intentionally not an engine — it makes the placement decisions explicit, then exports scaffolds for whatever actually runs the model.

1 — cluster.yaml / .jsonDescribe the hardware

Nodes, GPUs, VRAM, memory bandwidth, network links. Physics only — no vendor, no engine.

2 — plan.jsonGenerate a placement plan

Deterministic, bandwidth-first pipeline stages with KV-cache headroom. Same manifest, byte-identical plan, forever.

3 — scaffoldsExport & launch

Launch scripts and placement notes for llama.cpp RPC, EXO, Petals, or torchrun. Engines are plugins; plans never name one.

Live demo — plan a salvage cluster

This is the actual planner, ported line-for-line to JavaScript and verified against the reference implementation’s golden files. It runs entirely in your browser — no server, no dependencies, one HTML file. Edit the manifest, or click a GPU to kill it and watch the plan reroute; when too much hardware dies, the planner refuses honestly instead of emitting a plan that will OOM.

Quickstart (the real thing)

pip install -e .            # zero dependencies; add '.[yaml]' for YAML manifests

axm-zombie plan examples/cluster_4x3090_singlebox.yaml --out plan.json
axm-zombie export llamacpp plan.json --outdir out_llamacpp

# GPU 3 on node-a died:
axm-zombie replan cluster.yaml --lose node-a:3 --out plan.json --manifest-out cluster.json

# Prove the toolchain is alive (no network, no third-party deps):
python tests/golden_check.py

Built to survive

Artifacts are the API.

Plain-text manifests and plans with a frozen, versioned schema (SPEC.md). The code is a reference implementation — this page’s demo is the proof: the planner was reimplemented in another language from the spec and produces identical plans.

Engines are presumed mortal.

Both original export targets stalled upstream within two years. Exporters are disposable plugins; the plan never names an engine. llama.cpp RPC is the current living target.

Zero dependencies, offline forever.

The core runs on the Python standard library alone. A one-command resurrection test proves the toolchain works from a bare clone with no network and no maintainer.

Dead hardware is boring.

A dead GPU is a manifest edit plus a replan, never an architecture meeting. Freeze recipes pin last-known-good driver stacks before vendors drop them (recipes/).
